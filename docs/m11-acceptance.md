# M11 导航采集与小程序内审核：实现与验收

更新：2026-10-17。当前交付为本机合成场景下可运行的 M11 主流程，沿用原生微信小程序、FastAPI 和 SQLite。真实医院采集、身份资格核验、现场实走与 AR 定位不在自动化验收结论内。

## 使用入口

本机现已预置 AI 图片、7 个测试任务与三个独立测试账号，可直接在工作台切换。账号、数据状态、图片及重新导入方式见[预置测试数据](../backend/fixtures/navigation-m11/README.md)。

采集审核入口为“导诊 → 顶部采集 / 审核”，或“我的 → 导航采集与路线管理”。患者直接在“导诊”页搜索和选择已发布路线。

导诊首页已移除硬编码科室、演示地图、计时移动圆点、固定距离 / 预计时间及示例抽血安排。首页从 `/navigation/routes` 读取当前账号所属院区的已发布路线，显示起终点、楼层、节点数、楼梯提示和审核日期；搜索只匹配这些已发布数据。未登录、服务失败、尚无发布路线和搜索无结果分别显示，不用模拟路线补位。

这是照片导览，不是实时定位或 AR。详情页先展示起终点和实拍照片，用户主动确认在起点后再开始；开始前再次校验发布状态和版本。导览照片保持完整比例、可放大，只有用户点击才切换节点；每 15 秒仅复核有效性，不自动前进、不自动判定到达。路线版本改变会暂停并要求返回重新确认起点。

工作台提供明确标注的三种合成身份；切换时注销旧令牌、取消旧请求，清空页面中的私有内容，不自动授予患者 AI 或病历授权。

| 身份 | 后端账号 | 操作 |
| --- | --- | --- |
| 演示采集者 | demo-volunteer-001 | 领取任务、草稿、节点拍照、补拍、提交及查看审核结果 |
| 演示审核员 | demo-reviewer-001 | 同院他人提交、私有照片、退回、实走记录、发布、停用及用户反馈 |
| 合成患者 | demo-patient-001 | 已发布路线、照片导览和问题反馈 |

这是公开的演示身份选择器，不是生产身份认证。真实微信/手机号登录并不自动获得采集或审核权限，权限读取 navigation_memberships，不能从前端自行提交角色。

## 运行

项目根目录：

~~~powershell
.\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements-lock.txt
.\backend\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
~~~

以微信开发者工具导入项目根目录。模拟器与服务在同一电脑时，miniprogram/config/index.js 的 baseURL 应为 http://127.0.0.1:8000/api/v1，并在本地开发设置中关闭合法域名校验。本轮保留工程原有的局域网 baseURL 配置，没有替换用户已配置的地址；测试会注入临时端口，不能证明原局域网地址仍可访问。真机不能使用手机自己的 127.0.0.1，另行配置可访问服务与正式 HTTPS 域名。

新增 Pillow 用于解码、重编码图片。不会调用外部模型，也不需要模型 Key。图片只保存在 SQLite BLOB 中；备份需同时包含新增版本与照片表。

## 手工验收路径

1. 在工作台选“演示采集者”，领取“大厅→检验科”任务。领取后直接进入草稿；重复点击或重进任务恢复同一草稿。
2. 录入起点、终点；按需在终点前添加转弯/地标/电梯/楼梯。每个节点必须填写楼栋 / 楼层与位置说明，再填写方向、障碍及通行条件；可以先存不完整草稿，但缺失必填信息不能提交或批准发布。
3. 每个节点点击“拍照 / 选图”。先显示待上传预览，可点开大图、编辑照片或重拍。照片不自动上传；明确确认后才上传。微信版本不支持照片编辑时提示重拍或选择已处理的照片。
4. 所有节点照片上传完成后勾选隐私确认，提交审核。文字草稿可独立保存；尚在预览中的照片不能冒充上传成功。提交后冻结编辑。
5. 切换“演示审核员”，在“他人提交与发布管理”打开路线，查看照片。填写明确的补拍原因并退回；再以采集者补拍并重新提交。
6. 审核员检查照片，填写实走日期、障碍与通行条件，并确认独立实走，再“审核并发布”。勾选及文字只记录人工声明，不能证明真正到过现场；生产验收必须实际实走。
7. 切换“合成患者”，返回底部“导诊”Tab，从首页搜索科室、起点或楼层并打开已发布路线。核对起点照片并选择“我在起点”，开始逐节点照片导览，也可反馈封路或指示问题。未发布提交与历史照片不可见；静置页面不会前进或自动到达。
8. 审核员可查看反馈，填写原因并停用。患者列表、详情和照片接口不再提供该路线。照片导览在开始、回前台、每次换步及前台每 15 秒复核状态；服务不可用时暂停，清空指引。
9. 审核页查看提交历史版本：旧节点、照片、退回原因和操作人仍保留。旧版本为只读，不能拿旧审核版本直接审批新提交。
10. 原采集者在已发布或停用路线的采集页，选择历史版本并“恢复为草稿并重新审核”。当前路线暂时下线；修订或回滚后重新提交，必须经他人实走复核才再次发布。

开发者工具模拟拍照、页面逻辑模拟和真实手机拍摄是不同验证。全流程测试使用合成图片替代物理相机，不能据此声明真机权限或医院现场效果已经验证。

## 状态与约束

领取任务后：草稿 → 待审核 → 退回补拍 → 再次待审核 → 已发布 → 已停用。

- 一个任务只有一份工作提交。BEGIN IMMEDIATE 串行化领取、建草稿和发布；他人已领取的任务返回 409。跳过领取或代他人建草稿返回 403。
- 所有修改、上传、提交、审核与停用都会推进 revision；相同内容保存为无变更操作。旧 revision 返回 409，避免旧审核页批准新提交。
- 提交、审核、停用的同账号同内容重试只返回已有结果，不产生重复发布。反馈按用户和 request_id 去重；重用编号提交不同内容返回 409。
- 即使同一账号同时拥有采集和审核权限，也不能批准或退回自己的提交。服务端也禁止采集者以审核员身份停用自己的路线；审核队列不显示本人提交。
- 医院范围依据任务所属医院校验，不能随采集者后来变更所属医院而转移路线权限。
- 起点和终点必须唯一且位于首尾；节点有照片才可提交。删除节点清理当前照片；改节点类型或楼层使原照片失效，需要重拍。
- 照片最大 5MB，解码后最多 2400 万像素，只接受可解码的 JPEG/PNG；去掉 EXIF/GPS 后重新编码。不提供自动人脸检测或可靠自动脱敏，采集者仍须预览检查、编辑或重拍。
- 草稿照片限本人；待审及历史材料限本人和同院审核员；人工审核发布后的当前导览照片可供同院登录用户读取。历史照片始终私有，停用立即收回患者照片接口访问。
- 页面内和下载请求使用身份版本守卫，注销/切换会中止旧请求。导览临时文件不做离线地图缓存，离线不可继续显示受影响指引。
- ar_ready 始终为 false。发布照片导览不等于完成坐标标定、定位、路线规划或无障碍路径规划。
- 已发布或停用路线可由原采集者选择历史提交版本恢复为新草稿，用于修订或回滚；先下线当前路线并恢复任务到采集中，再提交、独立实走审核后发布。不能绕过复核直接重新发布。

## 数据与接口

数据库版本提升至 5，增量创建 navigation_versions、navigation_version_media、navigation_events、navigation_feedback_requests。保留原表、用户和数据；旧库缺少的 openid/phone 字段可补齐。历史快照从升级后的提交开始记录，不能反推旧库中未曾保存的历史。

节点与照片快照在提交事务中一起保存。照片重拍只替换当前版本，旧提交照片保存在版本表；审核与停用记录包含操作人、版本、原因和时间。SQLite 仍未加密，这些记录也不是防篡改存证。

以下路径均有 /api/v1/navigation 前缀，均需 Bearer：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | /me、/tasks | 当前权限、任务及本人已有草稿 |
| POST | /tasks/{id}/claim | 领取，支持本人重试 |
| POST | /submissions | 领取后创建或恢复同任务草稿 |
| GET | /submissions?scope=mine 或 review | 本人提交或同院他人审核队列 |
| GET / PUT | /submissions/{id} | 查看 / 更新可编辑草稿 |
| POST | /submissions/{id}/media | multipart 上传，返回 submission_revision |
| GET | /media/{id} | 鉴权读取当前照片，Cache-Control: no-store |
| POST | /submissions/{id}/submit | 隐私确认、冻结内容、保存快照 |
| POST | /submissions/{id}/review | approve / request_changes；独立审核与必填意见 |
| POST | /submissions/{id}/disable | 同院他人已发布路线停用 |
| POST | /submissions/{id}/revise | 原采集者按 source_revision 恢复历史稿，当前路线下线，重新审核 |
| GET | /submissions/{id}/versions/{revision} | 私有历史节点与照片索引 |
| GET | /submissions/{id}/versions/{revision}/media/{node_key} | 私有历史照片 |
| GET | /routes、/routes/{id} | 仅已发布版本，含 start / end（位置说明与楼层）、node_count、floors、has_stairs；详情另含节点和照片索引。不返回采集者、审核意见或历史材料 |
| POST | /routes/{id}/feedback | 反馈去重；审核工作台可见 |

## 调研采用的模式

[HOT Tasking Manager](https://github.com/hotosm/tasking-manager)将地图任务交由采集者完成，再由验证者检查；其[验证说明](https://hotosm.github.io/tasking-manager/validation/)明确不验证自己的工作。本模块采用领取互斥、采集审核分离，并把禁止自审落实到后端。

[ODK Central 的提交管理](https://docs.getodk.org/central-submissions/)提供提交审核状态、编辑记录与讨论。本模块采用明确的退回理由和不可覆盖的提交快照，并额外约束只有已发布当前版本可用于导览。仅参考流程模式，没有复制上游源码。
