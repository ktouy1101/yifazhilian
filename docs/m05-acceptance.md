# M05 医学知识科普智能体：使用与验收

> 2026-10-21 第一版闭环。**不是诊断工具，不替代医生，不调整处方。**
> 这一版把医学问答从“单轮检索 + 模板”推进到“分类 → 边界拦截 → 知识检索 → 生成 → 合并追问”的固定工作流；多轮上下文、知识运营后台、向量检索和真实医院工具仍未完成。

## 0. 它到底做什么

一句话：**它不看病、不开药，只把医生已经说过的话解释清楚、按医嘱做提醒、在特殊情况下提醒患者询问专业医护。**

> 这段定位用于服务端规则、提示词和运营文档，**不在页面上逐条展开**。页面只显示简短欢迎语和必要免责声明，例如“以上由 AI 助手整理，供理解参考；具体以医生、护士的说明为准”。

### 只做三件事

1. **解释医生的话**：把诊断、检查目的、报告指标、用药目的和注意事项讲成大白话；说明“单看这些信息不能确定什么”；把还要向医生核实的问题列出来。
2. **按医嘱提醒**：提醒复诊时间、用药时间、检查前准备、需要记录的症状；提醒内容来自患者录入的计划或医生安排，不是 AI 生成的处方。
3. **特殊情况提醒**：出现胸痛、呼吸困难、意识改变、大出血等危险信号，或患者有过敏、孕产、儿童、老年、肝肾功能不全、正在用抗凝/激素/止痛药等情况时，提醒询问专业医护或药师，不自行处理。

### 不做的四件事

- **不诊断**：不回答“我是不是得了某某病”“严不严重”“是不是误诊”；只解释判断需要哪些依据，并给可点击的追问建议。
- **不开药、不调药**：不推荐药名、剂量、疗程，不建议停药、换药、加量、减量或补服；只解释医生已开药物的目的和常见注意事项。
- **不替代就诊或急诊**：不判断“要不要去医院”“挂哪个科”；危险信号直接建议按床旁呼叫铃、找现场医护或拨打 120。
- **不判断医生对错、不评价医院责任**：不判定误诊、过错、赔偿；这类问题转到“问医生/医务科/法律模块”，并提示保留病历和沟通记录。

### 回答口径

- 用户问“这个药怎么吃”：按医嘱解释用法和提醒，不调整剂量；有疑问让患者找开药医生或药师。
- 用户问“我是不是……”：不判断，改为解释指标/症状的常见含义和需要补充的信息。
- 用户问“要不要停药/换药”：明确不要自行调整；出现出血、皮疹、呼吸困难等立即找医护。
- 用户描述急症：先给现场求助路径，不继续科普，不声称已通知任何人。
- 所有回答都像医护在说话：第一句用日常话直接回答是什么/为什么/怎么办，随后 2—3 条短要点；只有存在需要及时处理的情况时才加一句“注意：……”。整段控制在 180 个汉字左右，不用“结论：”“大白话：”这类标题。
- 正文不再重复“可以问医生 1/2/3”清单；后端不再计算或返回 `suggestions`（该字段于 2026-10-24 删除）；也不再在正文重复免责声明。

## 1. 用户入口

- 首页「健康知识助手」 → 聊天页（`pages/chat/index?domain=medical`）。
- 健康页主动提示条、检验单/病历页的“问智能体”也进入同一聊天页。
- 快捷问题：`胸闷 / 心慌要叫医护吗`、`这个药是做什么的`、`报告怎么看`、`医生这句话什么意思`、`复诊要带什么`、`出现什么要叫医护`、`病历还缺什么`。

聊天页在演示模式（未连接本机服务）使用本地模板；连接并授权后，医学问题走后端真实链路。

## 2. 服务端流程

`POST /api/v1/conversations/{id}/messages` 在医学域按以下顺序处理：

1. **身份与用途授权**：校验 `ai_medical` 的接收方、告知版本、有效期和撤回状态；网络调用前和保存前各校验一次。
2. **既有本地就诊分支**（`rag.answer_visit_question`）：诊断解释、误诊/责任、停药换药、复诊、危险信号、病历缺项。命中时直接返回本地结果，不调用外部模型。
3. **医学计划**（`medical_agent.plan`）：把问题分为 `crisis / urgent / medication / diagnosis / procedure / report / symptom / lifestyle / general`，同时识别主题（血常规、肝功能、肾功能、血糖、电解质、凝血、尿常规、心电图、影像、用药、手术麻醉、住院照护）。
4. **边界拦截**（`medical_agent.boundary_answer`）：
   - 急症/紧急：只给现场求助和联系医护的提示，声明不派出急救、不通知医护。
   - 个人诊断：不判断“是不是癌症/严重吗”，改为解释需要哪些依据，并给可点击的追问建议。
   - 用药调整：不给停药、换药、加量、减量、补服建议；可以检索用药安全知识并给可点击的追问建议。
5. **知识检索**：`knowledge.search` 只读同域、已发布且在有效期内的片段，默认取 3 条；来源信息只在服务端用于生成，不再回传前端或保存到消息。
6. **生成**：有外部 AI 授权时由 Provider 基于“当前合成问题 + 同域参考片段”生成；否则用本地模板。返回正文和 `disclaimer`。
7. **结构化收尾**（`medical_agent.enrich`）：统一补充 `category`、`topic`、`topic_key`、`external_ai`，再保存消息和元数据。

`message_metadata` 保存结构化字段，历史回看时由 `conversation_dict` 只还原公开字段；不再保存来源，旧库里的 `followups`/`doctor_questions` 也不会再暴露。

## 5. 边界与已知限制

- **不诊断**：不回答“我是不是得了癌症”“严不严重”“还能活多久”；只解释判断依据和需要问医生的问题。
- **不调整处方**：不提供停药、换药、加量、减量、补服剂量；只给核对与求助路径。
- **急症优先**：胸痛、呼吸困难、意识不清、大出血、黑便、呕血、晕倒等先给现场求助提示；聊天不会通知护士、不会派出急救。
- **不读未授权资料**：医学个体数据仅在对应授权有效时使用；外部 AI 只接收当前问题与同域公开参考片段，不接收病历原文或历史消息。
- **不是多轮工作流**：每轮独立，未实现跨轮事实槽位、检查结果追问、用药清单联动。
- **知识库是演示数据**：未接入医院审核知识、官方指南全文、医学知识图谱或向量库；引用不等于逐条证据核验。
- **外部模型不可用**：返回明确失败或本地模板，不伪造“AI 已回复”；未配置密钥时走本地路径。

## 7. 手工验收建议

1. 连接本机服务，授权 `ai_medical`（只问合成问题）。
2. 依次问：
   - `转氨酶偏高是什么意思`：应出现肝功能主题、引用，追问和问医生建议合并去重后展示为 chips。
   - `我是不是得了癌症`：应拒答判断，给可点击追问建议，不返回来源字段。
   - `抗生素有哪些副作用`：应给用药边界 + 引用，不建议停药。
   - `房颤平时要注意什么`：应出现“房颤与心律失常”主题，并引用 `med-515`。
   - `黑便怎么办`：应优先现场联系医护，不声称通知/派车。
   - `病历还缺什么`：应走病历清单分支，不调用外部模型。
3. 点追问 chip，应直接发送并生成下一轮回答。
4. 退出重进会话，历史消息的主题和追问建议应保留。
