# M03 病历上传、本地 OCR 核对与版本归档

交付日期：2026-10-17（北京时间）。接入现有原生小程序与 FastAPI，不使用网页或云 OCR。

## 入口与使用

“健康 → 检验单与病历”。原有文字笔记已合并到本页下方的“病历笔记”区，不再单独占“我的”入口。登录患者账号后，阅读“本地病历处理”告知并单独授权；当前版本为 `records-local-3`，接收方为 `local_record_service`。旧 `demo-1`、`records-local-2` 授权需要重新阅读当前告知。

## 病历完整性清单（2026-10-20）

- 资料类型扩展为：检验单、检查报告、影像报告、门诊病历、入院记录、出院记录、病案首页、手术记录、麻醉记录、病理报告、医嘱单、处方、诊断证明、费用清单、其他。
- `GET /api/v1/record-documents/checklist?scenario=outpatient|inpatient|followup` 返回门诊/住院/复诊三种清单；每项区分“已归档 / 已上传待核对 / 未上传”，并显示必需/可选。
- 医学智能体新增本地 `local_record_checklist` 分支：患者问“病历还缺什么/资料齐不齐”时，按当前已归档资料回答缺少哪些类型、哪些待核对；需要有效 `records_read` 授权，不调用外部模型。
- 清单只判断**资料类型完整度**，不判断医院诊疗是否完整、不判断诊断对错，也不推断医院是否“应该给”某份文件；缺少文件不等于医院责任。
- 当前仍是一张图片一份资料，不支持 PDF、多页分组或“医院已提供但我没有上传”的标记；这些是下一步工作。

验证：`test_record_checklist.py` 覆盖门诊/住院/复诊规则、已归档/待核对/缺失、完整性接口和智能体回答；后端全量 **166 passed**；前端全量 **83 项，受限沙箱 82 通过、1 跳过（M11 子进程），完整权限 83 通过**。受限沙箱中 M11 子进程和健康页本地 HTTP 用例可能因 `EPERM` / 临时库权限失败，均非页面逻辑。

1. 核对页提供独立的“从相册选择”和“拍照”按钮，进入页面不自动打开系统选图器，两个入口可随时切换。选择本人真实检验单或检查报告的单张 JPEG / PNG / WebP（8MB以内、2000万像素以内），在上传预览检查清晰度；保留项目、结果、单位、参考范围和报告日期，无关信息先在相册遮挡，再选图。勾选“我确认这是本人的检验单或检查报告，且已检查照片内容”后上传。
2. 明确点击上传后，私有原图保存在本机 SQLite。相同账号重复上传同一文件会打开既有资料并提示，不创建重复归档。选择照片或取消选图不会上传。
3. 点击“开始本地识别”。电脑端独立 Python 3.12 CPU 进程运行 RapidOCR，普通后端仍使用原 Python 3.14。手机需要连接本机服务；不是手机离线 OCR。
4. 在同一页面查看原图、放大照片、定位每项对应裁剪区域、查看OCR原文。编辑项目、结果、单位、参考区间，补充漏项、移除误提取项，并核对资料日期、机构与就诊事件。低于90%的行标记重点核对，但高分也可能识别错误。
5. 每项单独勾选；修改某项会取消该项勾选。核对资料信息并确认没有遗漏后，明确确认归档。缺少确认不能归档；仅保存草稿不会显示已归档。
6. 归档后可更正。填写更正原因、重新核对后产生新版本；旧版本、原照片、原识别值与修改前后值保留。历史快照只读；已归档资料不能通过“删除草稿”清除。
7. 列表可按待处理/已归档筛选，并按标题、机构、日期、就诊事件搜索。同一就诊事件填写相同名称即可检索同组资料。

OCR失败可重试、重拍或手填，失败不伪装识别成功。重拍新建资料，旧草稿保留；可明确放弃未归档草稿。网络超时后先“重新载入”核对服务端状态；重复归档请求复用操作编号。OCR进程超时75秒退出；服务中断遗留作业100秒后可重试或手填。识别作业、草稿及归档都持久化，重启后可恢复。

## 安装与运行

当前电脑已安装并实测独立 OCR 环境。新环境在项目根运行：

```powershell
.\setup-ocr.ps1
.\start-backend.ps1
```

需要 `uv` 与联网安装一次依赖。锁定清单 `backend/requirements-ocr-lock.txt`；直接依赖见 `requirements-ocr.txt`。安装不改动后端 `.venv`。若自备兼容环境，可设置 `YIFAZHILIAN_OCR_PYTHON` 为其 Python 绝对路径（进程环境变量）。`.ocr-venv`、模型、数据库与运行材料均不入 Git。

RapidOCR 1.4.4 的模型随 wheel 安装。执行时读取 stdin 图像，不用公开URL或外部AI；关闭 ONNX Runtime 遥测、禁止 worker 的 Python socket 连接，无运行时下载或云回退。无法运行时保留原图并显示可恢复错误。

## 数据与权限

SQLite schema 6在现有 v5 上增量建表，保留笔记、身份、授权及M11资料。

|表|职责|
|---|---|
|`record_documents`|所有者、原图原始字节与哈希、方向归一化尺寸、当前草稿、状态、并发revision、最新归档版本|
|`record_ocr_jobs`|每次识别任务、原文、置信度、坐标、原始字段、结果与失败信息|
|`record_document_versions`|确认版本的完整快照、对应OCR任务、图片哈希、更正理由、修改前后值|
|`record_document_events`|保存/确认请求的幂等编号、提交内容与时间|

图片、裁剪图、草稿、OCR原文、历史版本全部要求患者角色、账号所有权与有效用途授权；没有公开静态文件URL。长时OCR返回前再次检查同一授权和会话，撤回、撤回后重新授权、退出登录时丢弃结果。前端切身份取消请求，清空页面和下载缓存；到期清空当前展示。2026-10-18按用户明确要求，M03入口改为管理本人真实资料，取消仅限虚构资料的产品要求。当前数据库仍未加密，公开演示登录和开发验证码也仍存在；该字段调整不代表生产身份、存储和部署保护已完成。自动化测试继续使用合成样本。

归档版本不可由更新接口覆盖；所有变更使用事务。AI问答未增加病历读取工具，任何草稿或已归档资料都不会自动进入模型上下文。数据库管理员仍可修改本机文件，版本历史不代表防篡改存证。

## API

统一前缀 `/api/v1/record-documents`：

|方法与路径|作用|
|---|---|
|POST /|multipart字段 `file` 上传原图；重复返回 `duplicate=true`|
|GET /|本人资料列表|
|GET /{id}|当前草稿、OCR结果、任务及版本摘要|
|GET /{id}/image|方向归一化查看图；`?original=true` 读取未改动原始字节|
|POST /{id}/ocr|`revision, request_id` 本地识别|
|PUT /{id}/draft|保存核对草稿|
|POST /{id}/confirm|逐项确认后事务归档；更正需要reason|
|GET /{id}/versions/{version}|只读快照与修改记录|
|GET /{id}/jobs/{job_id}|指定作业原始识别结果|
|GET /{id}/jobs/{job_id}/fields/{field_id}/image|本人鉴权的原图定位裁剪|
|DELETE /{id}?revision=n|删除未归档、非运行中的草稿与其照片/任务|
