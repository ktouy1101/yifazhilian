# 医法智联学生项目骨架

原生微信小程序 + Python FastAPI 的本机演示工程。重点演示按用途授权、医学/法律分库检索、引用来源、紧急事件幂等与真实状态提示。

## 范围

- 全部数据为合成演示数据；小程序内王*兰等信息为用户指定虚构案例。
- 默认模型是本地 MockProvider，未连接任何付费模型、医院、电话、律师或签名服务。
- 后端使用本机 SQLite，默认文件为 `backend/data/yifazhilian.db`，重启后保留授权、会话、体征和演示呼叫记录。数据文件未加密，只能保存合成演示数据，不得输入真实患者资料。
- 当前可运行链路：演示登录 → 单独授权 → 健康/法律问答 → 撤回后阻断；长按 → 本地接收演示事件 → 状态显示。
- 导诊与知情同意书页面为明确标识的功能占位；OCR、真实微信登录、电子签署、通知投递、向量检索、志愿者工单均待实现。
- 设计图与 SQL 是后续开发规格，不代表代码已实现所有生产能力。

## 启动后端

安装 Python 3.11 或更新版本，在工程根目录运行 PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-lock.txt
.\.venv\Scripts\python.exe -m pytest backend/tests -q
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

打开 `http://127.0.0.1:8000/docs` 查看真实 API 契约。详细限制见 [后端说明](backend/README.md)。

SQLite 随 Python 提供，无需安装数据库服务。首次访问需要数据库的接口时会创建数据库及表；`data/` 和数据库文件已被 Git 忽略。可通过 `YIFAZHILIAN_DB_PATH` 指定其他本机文件路径；权限到期与撤回仍会在每次访问时校验，重启不会重置授权。备份请遵循后端说明中的 SQLite 在线备份方法，不要在写入时只复制主数据库文件。

## 启动小程序

用微信开发者工具导入 `miniprogram/`，使用测试 AppID/游客模式。工程配置关闭域名校验仅用于本机调试。先启动后端，在首页进入演示，再到“我的”逐项授权；返回健康/法援页面提问。

`127.0.0.1` 只用于开发者工具与后端位于同一电脑的场景。真机及正式环境必须替换为合法 HTTPS 域名，并开启域名校验。本工程不暴露到局域网或公网。

无 npm 前端依赖。可执行 `node --test tests/miniprogram-safety.test.cjs` 检查呼叫组件的取消与重试行为。已验证后端 14 项测试（含SQLite持久化、并发幂等、隔离测试库与备份）和前端 2 项呼叫行为测试通过，另通过真实Uvicorn进程重启冒烟。JS 语法与 JSON 解析通过。尚未进行微信开发者工具编译与真机验收。

## 从附件获得的开发事项

原 HTML 的 `openSheet(html)` 与 `openRecord/openVolunteer/openSettings` 的 `openSheet(title, body)` 调用不一致，正文会被忽略，应在继续维护 HTML 时统一签名。本原生骨架不直接运行该 HTML。

附件中的“已履行法定告知”“已电子签署”“已接通”是模拟文案，不能作为真实证据。需要由医生确认、签名验证、接收方回执分别驱动状态。

## 生产设计

- 建议目录及边界见 [架构设计](docs/architecture.md)。
- 仓库对比和官方法源见 [调研记录](docs/research.md)。
- 生产表结构草案见 [数据模型](docs/schema.sql)，尚未应用到演示服务。
- 默认不采集身份证、人脸、精确定位。姓名/电话显示遮罩；健康正文和影像需字段/对象加密；授权患者与经核验医护可按必要范围读取精确临床值。日志只记录元数据。
- 展示遮罩不是匿名化；第三方模型出站需独立完成处理关系、目的、字段、接收方、期限、授权及影响评估。
- 医疗同意文书与个人信息处理授权分开存储；家属紧急联系人身份不自动授予病历访问或代签权。
- 上线前须完成真实身份与关系核验、加密与备份恢复验证、细粒度授权和撤回清理、医院及供应商协议、签署验证、预警审核、通知回执与安全/伦理适用性评估。本机持久化不代表已经实现生产合规存证。

## Git 协作

代码仓库为 [ktouy1101/penguin](https://github.com/ktouy1101/penguin)，本地 `origin` 指向该仓库。数据库、密钥、虚拟环境和原始附件保留在本机，不纳入版本控制。

采用 `main` + `codex/<topic>`，每个功能经 PR 合并；提交格式 `feat(scope): ...`、`fix(scope): ...`、`docs(scope): ...`。提交前执行后端与呼叫组件测试，并审查 `git diff --cached` 中没有密钥、病历、学号、电话或原始申报书。

开源项目仅用于架构调研，未复制其代码。正式引入依赖或源码前逐项核对许可证和模型权重许可。
